# sazeny 的实战踩坑精选

> 这是 sazeny 做项目时亲身踩过、并解决的关键技术难点。每条含「现象 → 根因 → 解决 → 收获」，供 HR 了解 sazeny 的排错思路和工程判断。

## 评测 hit@k=100% 的假繁荣

搭检索评测面板，Golden Set 10 题跑出 hit@3=100%，看似满分。排查发现知识库只有 11 个片段、问题从文档原样摘、没有负例，三者叠加让检索难度趋近于零。收获：任何评测先问「区分度够吗」——满分往往意味着评测太简单，不是模型太好。

## 改切法不触发增量重索引

把分块从固定长度改成递归字符切分后重建索引，sync_index 把文档全判 skipped。根因：索引指纹只 hash 了原始文本，没把「分块策略」纳入，算法变化对增量同步不可见。解决：把「分块版本号」拼进指纹，改切法 bump 版本号即自动重建。收获：增量同步要想清「什么变化该触发重建」——内容变靠内容 hash，算法变靠版本号。

## 计算器为什么用 ast 白名单而非 eval

给计算器工具选实现，直接用 eval 会让 `__import__('os').system(...)` 真执行，是任意代码执行漏洞。解决：ast 白名单——解析成语法树，只放行数字节点和白名单运算符，遇函数调用、属性访问一律拒绝。收获：任何「执行不可信输入」的场景都用白名单而非黑名单。

## ReAct 观察接地 + 三重防死循环

写 ReAct 主循环，要解决「工具结果怎么喂回模型」和「模型可能永不停止」两件事。观察进模型靠消息历史累积（assistant 原话 + user 的 Observation 回填），死循环靠三重终止（MAX_ITER 封顶轮数、连续相同观察强制断、Final Answer 正常退出）。收获：任何 Agent 循环都要想清「历史怎么累积 + 什么时候停」。

## LangGraph 把 while 循环翻译成图

已有手写 ReAct 的 while 版本，要理解 LangGraph 如何表达循环、多分支、终止。核心心智：节点不互相调用，只写 state + 靠边路由；return→写 next="end"，continue→条件边自循环，计数→state 字段。收获：需要「留档、插人工」的循环流程用状态机图表达，比手写 while 更利于加 checkpoint 和 HITL。

## update_state 外科手术式改字段不联动 messages

demo「回到过去改 arg 重跑」，答案仍不变。根因：update_state 只改指定字段、不联动其它字段——改了 arg，但 messages 里的旧历史还在，而 agent 读的是 messages 不是 arg。收获：凡「一个字段语义由另一字段派生」的场景，单独改派生源必然留下不一致，改之前先问「还有哪些字段和它联动」。

## 摘要缓冲区：省 token 但引入幻觉

给短期记忆加摘要缓冲区，发现两件事：运行变慢（每次溢出多一次 LLM 摘要调用）；答案里出现摘要凭空冒出的虚假温度。根因：摘要压缩≠无损，LLM 会脑补、扭曲信息。收获：摘要缓冲区是「延迟换 token」的权衡不是纯赢；任何 LLM 中间产物（摘要、翻译、改写）都可能引入幻觉。

## 长期记忆：覆盖写 vs merge + 触发时机

长期记忆 demo 里 remember 节点把第一次存的偏好覆盖丢了。根因：store.put 是覆盖写不 merge；且 remember 每次会话结束都跑，没有「只有新事实才写」的判断。收获：跨会话记忆要想清三件事——新记忆怎么和旧的合并、什么时候写、旧记忆会不会过期（时间衰减）。

## HITL 审批靠代码层，不靠提示词自觉

给危险操作写审批，担心提示词里写「需审批」会让模型自己拒绝、审批触发不了。解决：审批是强制卡点，必须由代码层（review 节点 interrupt）实现；提示词只描述「工具能干什么」，危险判定交给 DANGEROUS_TOOLS 分流。收获：任何安全、审批机制都该是代码层硬约束，不是提示词软请求。

## 换弱模型导致 ReAct 死循环

把 deepseek 换成免费 glm-4-flash 后，「我叫什么」这类问题全部死循环。trace 显示它调工具时输出 `calculator[1+1]`（漏 Action 前缀）或 `Action: None`，被严格正则 parser 抛 ParseError 打回，反复自循环撞 MAX_ITER。根因：严格 parser + 弱模型格式遵循差，是错配不是真死循环。收获：小模型在 ReAct 里更冲动、更易死循环，生产要么用强模型、要么必须有死循环护栏；且「单测全绿」≠「真模型联调通过」。

## Redis checkpointer 三连坑

把 LangGraph checkpointer 从内存换 Redis，连踩三坑：同步/异步 Saver 不匹配、裸 Redis 缺 RedisJSON+RediSearch、直接构造 Saver 不建索引。收获：接任何外部依赖都要摸清它到底依赖什么（要 Redis Stack 而非裸 Redis）、构造后记得 setup 建索引、且懒加载别在 import 时连。

## Docker 化：容器里 localhost 不是宿主机

Docker 化连踩四坑：容器连不上 Redis（localhost 是容器自己）、requirements 漏依赖、容器起了外网进不来（uvicorn 绑 127.0.0.1）、秘钥怎么进容器。解决：容器通信走服务名+环境变量、监听绑 0.0.0.0、秘钥用 environment 注入永不烤进镜像。收获：本机能跑 ≠ 能部署，镜像依赖必须和代码 import 对齐。

## 假死循环：写死 thread_id 续跑旧 checkpoint

换好模型后测试仍死循环，但用全新 ID 跑就正常。根因：写死的 thread_id 让每次进同一会话，从旧的 iteration=6 接着跑，第一行就撞 MAX_ITER 守卫——连模型都没调。收获：判断死循环先分清「模型真死循环」还是「续跑旧状态直接撞守卫」，查 checkpoint 的 iteration/same_count 即可。

## 护栏分类器坏 JSON 判安全 fail-open

LLM 分类器可能吐坏 JSON，直接 json.loads 会崩。解决：try/except 兜底，坏 JSON 判安全（fail-open）——宁可漏一个注入，不可误杀正常用户。收获：安全护栏的失败默认值要想清 fail-open（不误杀）vs fail-closed（不执行），护栏用 fail-open、扣费删库等危险操作用 fail-closed。

## 检索侧护栏：切点 + UNTRUSTED_TOOLS 集合

给检索结果加护栏，先写死 `tool == "search"` 被点出「不防漏」。解决：护栏放在所有工具结果进模型的统一入口（tools_node），「管谁」用 UNTRUSTED_TOOLS 集合标注，不写死工具名。收获：安全属性建模成集合、路由时查集合，扩展时不散落、不漏。

## 评测忠实度维度错位：诚实拒答被误判为编造

第一版评测知识库事实题忠实度全 0，但轨迹显示 agent 其实是诚实拒答、根本没编造。根因：忠实度 rubric 把「拒答」和「编造」都打 0，两者性质相反。解决：忠实度明确「诚实拒答=没编造=满分」，相关性明确「没回答=0 分」。收获：LLM-as-Judge 的维度要对准失败阶段——检索失败、编造、跑题是三件事。

## Golden Set 要可验证

天气题 agent 忠实转述了真实天气，裁判却打 0。根因：非确定性题目标准答案不可验证，裁判只能瞎猜。解决：把天气题从 Golden Set 删掉，只留「标准答案可验证」的题；非确定性题要么 mock 掉工具再进评测、要么排除。收获：评测题必须标准答案明确、可验证。

## 代码执行沙箱：空 builtins 连 print 都禁

给 code_worker 写 run_python，用空 `__builtins__` 想禁 __import__，结果 print 也被禁、拿不到输出。解决：白名单——只放行 print，仍禁 __import__/open/eval。收获：沙箱要白名单不是黑名单；且空 builtins 仍能被 `().__class__` 逃逸，真生产要 Docker/子进程沙箱。

## A2A 路由：客户端指定 + 默认值会瞎路由

给 A2A 的 SendRequest 加默认 skill，客户端不指定时问天气也会默认走 search。根因：默认值 = 写死的一种。解决：换服务端路由——客户端只发任务，由 supervisor 按任务内容决定路由。收获：要运行时决定就用 router，别用默认参数糊弄。

## search 混合检索：复用而非重写

准备手写 BM25+RRF 升级 search 时，发现阶段0 的 RAG 项目里已有完整实现，等于要重写一遍自己写过的代码。解决：复用 RAG 的纯模块（BM25、tokenize、RRF、embed），自己写薄壳；HYBRID_WEIGHTS 按新场景重设。收获：复用前先查已有项目；复用代码分两半——逻辑照抄、参数重设。
